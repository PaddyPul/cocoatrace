# Private evidence recovery rehearsal

UPL-018; OPS-002 remains a managed-provider gate. Run `npm run test:recovery:docker` with Docker Desktop. The existing full release and recovery CI job run this once; no additional focused run is needed for ordinary acceptance.

The fixed `cocoatrace-recovery-tests` Compose project owns a tmpfs PostgreSQL16 instance and unexposed Moto5.2.3 service. The script accepts no customer database or S3 endpoint. It migrates the source database, archives two versions of a synthetic private PDF plus a separate deleted object/version marker, then permanently deletes the entire original source bucket before recovery. A custom PostgreSQL dump is restored into a separate fresh database. Objects are restored into a different versioned bucket with AES256 encryption, private ACLs and public access blocks.

S3 does not preserve original version IDs on PUT. The private disposable archive retains source IDs and a separate original-to-restored map; verification checks every mapped version, current-head flags and deletion markers. A deleted object must remain absent through a normal current-object GET. Historical versions are verified by exact SHA256, byte size and MIME. The current restored object is independently checked against the storage key, hash, size and MIME queried from the restored database. The database comparison also preserves logical schema, forward migration ledger, linked organization/user/farm/batch/evidence records and audit history.

Two runtime canaries add an unexpected corrupt current version and remove a historical version. Both must fail verification. The rehearsal then reconstructs a clean target before its final metadata/object cross-check. Inventory is bounded to100 rows and fixture objects to64KiB; truncation or overflow fails, never implies complete recovery. Archive members are read by name without filesystem extraction.

The temporary archive, source/restored version IDs, map and bytes stay inside the disposable Moto container. No real signing secrets or production credentials are backed up here. `finally` removes only the fixed disposable project, even when object archival fails. `recovery-test-results/summary.json` contains status, commit, timestamps, scope and verified check names, without object bytes, version IDs or personal records. CI retains this safe summary for30 days. A cleanup failure also fails the rehearsal.

## Hosted operator acceptance

This is an executable synthetic recovery test, not a deployable backup service. Before closing OPS-002 or admitting customer data, the named owner must select independent encrypted database/object backups, permissions, retention/legal holds and agreed RPO/RTO. Exercise provider-native version/deletion-marker export, pagination and customer-sized restore with the selected provider; record account, region, cutoff, durations, inventory reconciliation and approval privately. Provision a separate restricted restore target, stop background writers, restore compatible database/object snapshots, validate every referenced object/hash/version and unknown/missing items, then revalidate current application authorization before reconnecting users. Do not reissue old signed URLs or copy active sessions into an exposed rehearsal. Missing evidence keeps access unavailable; never mark a document clean merely because backup bytes exist.

If recovery fails, keep production unchanged and the restore target isolated. Repair/repeat from an independently verified backup; do not rewrite immutable evidence hashes or erase deletion markers to make comparisons pass. Never run this disposable script against actual provider buckets. Local success does not demonstrate managed backups, legal erasure, immutable retention, external disaster isolation or customer-volume recovery time.
