# Payment deadlines and reminder operations

Terms-confirmed deposits/prepayment and presented-document installments become due at their recorded trigger timestamp. Delivery credit becomes due at delivery plus agreed credit days. Replaying a trigger cannot extend deadlines or reopen paid/submitted installments. Migration 027 backfills only null due dates from known stored trigger timestamps on agreed, open contracts; missing historical triggers remain unresolved instead of inventing dates.

The API runs a nonoverlapping payment worker every 15 seconds. Automatic reminders begin after 24 hours overdue. Manual supplier reminders can be earlier. Both share one installment/UTC-day unique reminder, atomically audited and queued. Payment submissions, paid installments, closed/unagreed deals and unresolved payment or delivery disputes pause reminder generation. Active buyer members with payment.read or wildcard permissions are eligible; tenant membership, permissions and payment state are checked again before email submission. Stale older reminders are suppressed when a newer daily reminder exists.

Emails contain amount, currency, deadline and an authenticated deal-room link; no bank reference or evidence attachments. Outbox leases last five minutes, failures retry up to eight attempts with bounded delay, and terminal failures require operator attention. SMTP delivery is at least once: a crash after relay acceptance can duplicate a message. Sent means relay acceptance, not verified inbox delivery. A short contract lock spans SMTP submission to serialize with payment/dispute changes; existing SMTP timeouts bound this work.

EMAIL_DRIVER=smtp and IDENTITY_EMAIL_ENABLED=true enable configured SMTP. Without those settings, email work remains queued rather than falsely marked sent. Synthetic investor preview keeps outgoing email disabled. Local docker-compose.email-test.yml captures mail in Mailpit at http://localhost:8025, rather than personal inboxes.

Run npm run payments:remind for a bounded operational pass (or docker compose exec api npm run payments:remind). Its JSON reports created, sent, suppressed, failed, skipped and terminalFailures; failure exits nonzero. The queue survives restarts. Inspect failed_terminal rows using approved database access and redacted logs; fix provider configuration before retrying terminal rows under an audited maintenance procedure. Do not delete reminder history to force duplicates. No automatic bank debit, provider payment settlement or fee collection is introduced.

Automatic reminder audits use reserved non-login principal 00000000-0000-4000-8000-000000000001 with the affected buyer organization as audit scope. This identifier is not a users row, has no login credentials or roles, and is displayed as Scheduled payment worker. Human reminder audits retain the authenticated user identity. Existing NOT NULL audit constraints remain intact.
