# Workspace filters and support

Marketplace, Inventory and Offers support named presets. They store only validated filter/search fields on this device, separated by account, organization and register. Up to10 presets per scope and16KiB serialized storage per scope; names<=50, searches<=80. No automatic cross-account application, URL/token/payload storage or server record mutations. Applying any preset resets to page one, including reapplying unchanged values. Account/workspace changes clear parent search controls and hide old presets immediately. Blocked/quota/corrupt storage shows a session-only notice; unreadable bytes are preserved rather than silently overwritten. Presets are not synchronized across devices or shared with teammates. Logout does not delete that account's stored device preferences; use a trusted device.

The authenticated shell Report an issue entry carries only a fixed workflow context and optional exact UUID. It never copies the full URL, query string, document path, token or request payload. The reporter reviews subject/description and context. Entity references are user-reported context, not proof of ownership or platform access. Do not include credentials or sensitive documents. Requests go to the private application operator queue; no automatic email, external monitoring or response-time guarantee is introduced.

Submission returns a durable BT-SUP-UUID reference. If the result is uncertain within the current page, inputs freeze and Retry sends the exact same body/key; the server returns one record/audit for concurrent or repeated retries,409 if the key is reused for different content. Once confirmed a new report can be composed. Pending draft/key is in memory; do not navigate away while uncertain. If the page was closed, inspect private request history before composing a replacement. Requester history is visible only to that user in the current organization, including after page/search requests. Other organization members cannot inspect it. No anonymous intake or attachment download is added.

Wildcard platform administrators select the operator queue to review requests. A status change requires a10-character reason, live session/authority, fresh enrolled passkey assurance, observed expectedStatus and atomic audit. Stale status returns409; refresh then explicitly reload the selected record while retaining notes. Same-status notes are audited and replace the current operator note; prior reasons remain in audit history. Reporter body/reference are immutable; operator notes remain private, while the reporter can see status. Staff must choose a real monitoring owner and response practice before promising support coverage; OPS/ENV/SEC-019 remain open.

Migration043 adds support_requests, requester paging index, idempotency uniqueness and report-body immutability trigger. No secret/provider configuration, dependency or project/volume rename. Startup applies forward migrations. Use a reviewed forward correction for rollback; do not reset data or run npm inside the hardened API. Data retention/deletion and external escalation remain OPS-013/SEC-019 follow-ups. Full candidate native/browser release and required CI must pass before merge.
