# Shipment paging and totals

GET /shipments/page requires shipment.read and always restricts rows to shipment contract seller or buyer. Logistics assignment, coordinator label and generic read-all/admin grants do not broaden rows. limit 1–100 (default 50); search max80 literal characters over shipment/contract IDs, provider, booking/document/container, ports, milestone, coordinator and Incoterm; direction all|purchases|sales; status all|active|delivered|cancelled; milestone all or an existing supported milestone; opaque cursor bound to tenant/filters. UUID ascending order is stable, not chronological. Filter before limit; preserve existing payment-summary fields plus Incoterm. Existing bounded read-only repeatable-read snapshots/timeouts unchanged.

GET /shipments/summary requires the same permission/party boundary and returns count, active_count, delivered_count and cancelled_count, independent of search/page. Active excludes delivered reports and settled/cancelled contracts. Delivered means reported transport milestone, not buyer acceptance/payment/trade completion. Categories can overlap (cancelled contract with delivered report); do not add categories to infer count. No money total. Aggregate avoids payment joins.

ShipmentRecordsPage has server search, sale/purchase and transport-state filters, explicit page counts/navigation/retry, independent unavailable totals, and accessible Open transport buttons. List rows do not offer progress mutation actions. Incoterm and coordinator display remain data; existing detail permissions/payment gates/recall rules remain final and unchanged. Sales/purchases describe commercial parties, not transport recording authority.
