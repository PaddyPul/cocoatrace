# Irreversible action review inventory

Scope: the current React workspace and public entry forms. Review means the user sees the record and consequence before a named final write. A dedicated reviewed form is itself confirmation; ordinary creation/editing does not require a second generic dialog. Confirmation never substitutes for server permission, freshness or transaction checks. Closure is subject to integrated release acceptance.

| Mutation family                                           | Current review boundary                                                                   | Consequence / retained failure                                                      |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| Offer acceptance                                          | Contextual native confirmation, selected offer and fee rate snapshot                      | Creates contract and commits inventory; failed review retained                      |

| Device filters, shortlist, logout, ordinary record drafts | Reversible local actions, explicit named save, or existing unsaved-change review          | No destructive business transition; no redundant dialog                             |

Audit method: inspected mutation callers in pages and components, including API accept/reject/status/publish paths, window prompts and shared final-action forms. API-only administrative and genealogy primitives are not customer controls. No customer delete-all, blending or repacking entry is exposed.

Native dialog cancellation/Escape writes nothing. Busy controls prevent repeat submission. Dedicated forms retain normal error handling and unsaved guards. Review snapshots do not reserve server state: the API remains authoritative and can reject changes that became stale. Browser evidence includes confirmation cancellation, failed write retention and the existing full money/physical-trade journeys; founder release acceptance is required before marking the backlog item delivered.
