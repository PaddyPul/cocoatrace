# Authorization entry-point review — 14 October 2026

Backlog: SEC-001, SEC-006, QLT-002; CORE-tenant. This is a local engineering candidate, not a hosted penetration-test or universal resource-policy acceptance report.

## Checked surface

- 195 explicit method/path registrations across 25 source files.
- 178 routes require session credentials; actual Express registration equality and missing/invalid credential denial run without PostgreSQL. Protected GETs also deny implicit HEAD access.
- 155 routes declare named ALL/ANY permission gates, including inherited prefix guards. The new PostgreSQL suite supplies live zero-permission denial cases for every one.
- 23 session-only routes intentionally delegate self/organization/recall relationship policy. Session-only does not mean public or network authorized.
- 16 public/token entry points are explicitly reviewed exceptions: process/dependency metadata, login/reset, access requests, invitation capabilities and published product projections/scan recording.
- One upload-content endpoint authenticates a signed intent capability and uses the capability-aware pre-parser handler; it is not a public file-upload exemption.

The [machine register](route-authorization.json) records every method, path, source, ordered guard, control and handler, plus policy/regression pointers. Those pointers identify existing evidence; they do not assert all possible resource/role combinations were executed. The register gate fails on source drift, duplicate or unsupported routing, an unreviewed anonymous surface, permission-before-auth ordering or missing policy/evidence entries. Native runtime coverage remains mandatory. OPTIONS is a CORS protocol response, not a private resource view; implicit HEAD follows GET authorization.

## Concrete hardening

The six access-application review routes previously authenticated the session, then performed parameter/body validation before their controller/service required platform authority. The service already denied non-administrators. Each route now applies the same wildcard-administrator permission immediately after authentication. Unauthorized callers receive 403 before malformed ID, query or approval/rejection payload processing. Service/query authorization is retained. No platform role is granted or broader resource access introduced.

## Coverage and remaining acceptance

The source gate is not a proof that resource authorization is correct. Entry tests answer whether unauthenticated or permissionless callers can reach protected work. Separate resource tests must exercise authorized and unrelated UUIDs with actors holding the same ordinary permissions, role unions, suspension/revocation, buyer/seller action ownership, state changes and returned fields. Existing source/evidence/trade/payment/transport/recall/provenance/audit/admin suites are linked above and must remain green.

This candidate also adds a foreign-versus-absent recall response equality case and self-identity positive control. It does not homogenize every legacy resource response. Current entry convention is 401 for missing/invalid credentials and 403 for absent declared permissions; resource-level 403/404 policy still needs endpoint-class completion under SEC-006. Public projection/capability abuse and privacy tests remain independently required.

QLT-002 and SEC-006 are IN PROGRESS. Next: turn the per-resource/action foreign-ID and role-union/suspension inventory into explicit coverage with paired positive cases; retain existing party/state policies, and resolve each resource-existence convention. Hosted ingress, CSP/secrets, private-byte storage/recovery, external review and combined capacity remain separate gates. No completed-item percentage increase is taken from entry tests alone.

## Maintaining the register

Run `npm run check:authorization`; CI and verify:release enforce it. After reviewing a route change, edit its resource-policy/evidence entry if needed, then run `node scripts/check-authorization.mjs --update-routes` and review the JSON diff. Do not add public exceptions merely to make a failing check green. New router DSL/mount patterns require extractor/runtime-test support before acceptance. Every generated native permission case still requires a genuine session with no granted permissions; no mock grants or production security bypass is introduced.

Author results are in releases/AUTHORIZATION_ROUTE_REGISTER_WINDOWS.md. PostgreSQL/runtime acceptance is not inferred from compilation or evidence-file existence.
