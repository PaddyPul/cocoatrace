# Outbound URL review — 2026-10-14

Scope: SEC-009, current API and browser sources. This is a rendering/input-policy review, not a carrier-verification or DNS ownership claim.

| Surface | Source and policy | Finding / control |
| --- | --- | --- |
| Shipment provider tracking | Party-supplied `trackingUrl` | Storage and browser permit only HTTPS, no credentials, no custom port, bounded 2,048 characters, syntactic public DNS host. IP literals and local/reserved suffixes rejected. Browser rechecks legacy rows, displays destination hostname, uses `noopener noreferrer` and no referrer. Unsafe stored rows show unavailable text. |
| Product hero URL | Party-supplied `heroImageUrl` | Same validation on save; public JSON suppresses unsafe legacy values. Current public product page does not render the hero field. Future rendering must reuse the browser policy and no-referrer image setting; no remote-image proxy is introduced. |
| Product detail / QR links | Server-generated profile and QR addresses, validated slug | Browser profile button constructs a same-origin `/p/<encoded slug>` path rather than opening a returned absolute URL. QR image source remains a same-origin API path. Published QR absolute origins are operator-configured. |
| Public product list and investor demo | Validated product slugs / compile-time paths | Relative product links; fixed demo links use `noreferrer`. React text rendering, no HTML insertion. |
| Verification/invitation/reset links | Server-generated tokens using configured public origin | Existing email sender checks exact configured origin and HTTPS in deployed mode. Demo verification link is server-generated, not a supplied destination. |
| Audit/provenance downloads | Fixed API paths, IDs/filter values | Constructed same-origin API destinations; newly opened tabs use opener isolation. Blob downloads are generated by application code and revoked, not user-provided URLs. |
| Font stylesheets | Compile-time Google Fonts hosts | Fixed HTTPS hosts; no user-controlled URL interpolation. |
| Outbound API requests | OpenAI fixed HTTPS endpoint; configured S3 endpoint | No tracking/hero URL is fetched server-side. S3 endpoint and credentials are operator configuration; bucket/object paths are separately signed/encoded. |

## Policy decision

The allowlist is a scheme/authority rule, not a list of carrier brands: arbitrary registered logistics providers must remain usable. Allowing a syntactically public DNS name does not verify its ownership or resolve its addresses. Links can redirect and destinations can be malicious: no trusted-provider badge or endorsement is attached. Tracking opens only through an explicit user click with visible hostname; no background fetch, preview, proxy or redirect following is added by BetterTrade.

Production request security headers remain independent (CSP/security-header closure is SEC-008). Hero URLs are currently unused browser data, not an automatic tracking request. Existing invalid rows are preserved for audit/history but cannot become active tracking links. No migration required.

## Verification

- API utility and validation tests cover executable schemes, protocol-relative and HTTP URLs, credentials, custom ports, local names, IP representations, control characters, overlength values, absent legacy values, and a new provider preserving encoded reference parameters.
- `e2e/externalUrlPolicy.spec.ts` checks API/browser policy parity without browser launch; two browser scenarios verify that shipment tracking renders a host-labelled isolated HTTPS link and suppresses executable legacy URLs.
- Native release/browser execution remains the release owner's gate; local focused results are reported in the bundle handoff.

Engineering acceptance for SEC-009 can close with this source inventory and green release verification. No live external provider testing is claimed or required for this input/rendering review.
